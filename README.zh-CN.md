# 企鹅个体识别（Penguin Individual Re-Identification）

[English](README.md) | **中文**

给定一张**洪堡企鹅（Humboldt penguin）**照片，识别它是**哪一只**具体的企鹅（个体身份，非物种）。最终目标：游客拍一张照片，即可查出对应企鹅个体，以及它的名字、特征、习性。本项目所有个体均为同一种群的洪堡企鹅。

项目正从**分类 baseline** 演进为 **embedding 检索 + RAG** 系统——把每张照片转成向量，在向量数据库中匹配，再用 LLM 生成有事实依据（grounded）的企鹅介绍。一次**数据泄露审计**（[§5](#5-数据泄露审计与跨场次评估)）发现原来的头号数字被**训练/测试之间共享的同场次连拍**抬高了。在按场次的交叉验证下（[§6](#6-交叉验证下的度量学习)），识别达到 **macro rank-1 0.559**，基线为 **0.390**；完整的「损失 × 增强」四宫格显示其中**大部分来自数据增强**而非度量学习，而 ArcFace 的贡献随底库规模增大才显现。若在全群 81 只中排序，这个数字是 **0.477**；若还要求真陌生个体有 99% 被拒识，则只剩 **0.123**——**描述部署可用性的是最后这个数字，不是第一个**。本文所有准确率均为 **macro**：每只企鹅等权重，与它有多少张照片无关。剩余工作是档案/RAG 层与对话式界面。

## 1. 数据集

- 原始数据 `penguins_data/`：共 **81 只**企鹅、**2307 张**照片，每只照片数从 1 到 291 张不等，**长尾严重不均衡**。
- 按「照片数 ≥ 16 张」筛选出 **44 只**作为可训练个体（`penguin_image_count_summary.csv` 中 `selected=True`），其余 37 只（≤15 张）样本太少，暂不参与训练。
- 这 44 只里有 **35 只拥有 ≥ 3 个不同的拍摄场次**，是所有按场次划分的评估（[§5](#5-数据泄露审计与跨场次评估)、[§6](#6-交叉验证下的度量学习)）实际使用的个体。「场次」指一次拍摄产生的一串连拍，由文件名前缀与帧号识别。
- 已按个体切分为 train / val / test：`penguins_dataset_split/`。
- 肚子裁剪版本数据（由肚子检测器裁出）：`penguins_dataset_split_belly_by_yoloV8/`。

> 即便在筛选后的 44 类内部，样本量仍从 291（Medici）到约 16，最大/最小差约 18 倍，是后续所有难点的根源。见 [图 05](#3-实验数据记录图)。
>
> **覆盖面比准确率更硬：** 全群 81 只里有 37 只根本不在系统中，在补拍之前，无论准确率多高都识别不了它们。

## 2. 已完成的实验

| 实验 | 输入 | 模型 | 训练轮次 | best val acc | **test acc** |
|---|---|---|---|---|---|
| **exp1 baseline** | 全身照 | ResNet18（迁移学习） | 29（早停，上限30） | 0.907 | **0.950** |
| **exp2 belly** | 肚子裁剪图 | ResNet18（迁移学习） | 39（早停，上限50） | 0.867 | 0.866 |
| **belly detector** | 全身照 | YOLOv8s 检测 | 98 | mAP@50 ≈ 0.98 | mAP@50-95 ≈ 0.60 |
| **exp3 向量检索** | 全身照 | ResNet18 特征 + FAISS（免训练） | — | — | **0.959**（原型）/ 0.947（1-NN）/ 0.978（top-5） |

> ⚠️ **泄露提醒：** 上表 exp1（0.950）与 exp3（0.959）的准确率用的是**随机划分**，而且是**按图片算的**。后续审计发现同场次连拍会泄露进测试集、抬高这些数字。同一套流程在按场次划分下只有 **macro top-1 0.389**（[§5](#5-数据泄露审计与跨场次评估)）；换成 ArcFace 度量学习 + 5 折交叉验证后达到 **0.559**（[§6](#6-交叉验证下的度量学习)）。本节请当作历史记录，而非当前性能。

三者共用流程：
- `torchvision.datasets.ImageFolder` 加载
- 迁移学习（ImageNet 预训练 ResNet18）
- 类别不均衡处理：`WeightedRandomSampler` + 类别加权 `CrossEntropyLoss`
- 按验证集准确率保存最优 checkpoint，最后在 test 上评估并导出预测 CSV

**exp1（全身照）**——test accuracy **0.950**，best val 0.907（第 21 轮）。每类表现见 [图 04](#3-实验数据记录图)：样本多的个体（Cooper n=20、Ron_burgundy n=29、Medici n=44）几乎全对；出错集中在 test 只有 3~5 张样本的小类。

**exp2（肚子裁剪）**——test accuracy **0.866**，明显**低于**全身照的 0.950。其 val loss 始终高于 exp1（[图 01](#3-实验数据记录图) 右），泛化更差。

**肚子检测器（YOLOv8s）**——训练 98 轮，验证 **mAP@50 ≈ 0.98、mAP@50-95 ≈ 0.60**，precision/recall 约 0.95（[图 03](#3-实验数据记录图)）。权重：`runs/detect/runs/belly_detector/exp1/weights/best.pt`。检测本身够好，但裁剪会**丢弃脸/胸带/体型等身份信息**，且检测误差会传播给下游分类器——这解释了实验二为何更差。

**exp3（向量检索——旗舰方案的 CNN 路线）**——复用 exp1 的 ResNet18 作为**冻结的 512 维特征提取器**（去掉分类头），把 train+val 全部图片注册进 **FAISS** 向量库，对 test 照片用最近邻 / 类原型检索识别。**不做新训练。** 结果：原型（类均值）top-1 **0.959**、1-NN top-1 0.947、top-5 0.978——即检索式识别**追平/略超** softmax 分类器（0.950），同时得到一个可注册的向量库（新个体直接入库、无需重训）。代码：`embedding_id/`（`embedder.py`、`build_and_eval.py`、`identify.py`），这就是 `identify_penguin` 工具的可用内核。

## 4. 关键结论

1. **全身照 > 肚子裁剪（0.950 vs 0.866）。** 身份信号不只在肚子——脸部花纹、胸前黑带、体型比例都是线索。裁得太狠会丢信息，检测误差还会传播噪声。
2. **训练/采集标准 = 全身正面照。** 不再强求肚子清晰完整。
3. **只用正面。** 企鹅背部大面积均匀深色，个体间几乎无差别，正反混训会拉高类内方差、引入跨类混淆。线上系统对「非正面」照片应提示重拍，而不是硬给身份。
4. **数据是约束性瓶颈——但要分成两件事看。**
   - **覆盖面。** 全群 81 只里只有 44 只照片够训练、35 只场次够评估，其余 37 只根本不在系统中。这一层任何算法都无能为力。
   - **场次多样性。** 在这 35 只里，准确率跟着**每只鸟的拍摄场次数**走，而不是照片总数：3 个场次的鸟只有 0.19，7 个以上的达到 0.72（[§6](#6-交叉验证下的度量学习)）。同一串连拍里多按几张快门没有用，换一天、换光线再拍才有用。
   
   但模型侧**并没有到头**：在已经有 ≥4 个场次的鸟身上，从 softmax+basic 换到 ArcFace+strong 把准确率从 0.481 推到 0.669。完整的「损失 × 增强」四宫格（[§6](#6-交叉验证下的度量学习)）显示其中较大的一份来自**数据增强**（+0.141），而非度量学习损失（+0.096）。数据和方法是互补的两个抓手，不是二选一。

## 5. 数据泄露审计与跨场次评估

数据集里有很大一部分是**连拍序列**——同一台相机、同一时刻、连续帧号（如 `DSC_2743…2749`）。由于 `a.py` 对每只企鹅的照片**随机划分**，同一组连拍的近重复帧可能同时落入训练集和测试集；模型于是被拿"其实已经见过的照片"来考，准确率因此虚高。

**审计**（`analysis/leakage_audit.py`）——用与模型无关的信号（感知哈希、像素相关、EXIF 拍摄时间、文件名帧号）：
- **13.8%** 的测试图在 train+val 底库里有近重复；
- **97.8%** 与底库里的照片来自同一**拍摄场次**；
- 在有 EXIF 的照片中，约 29% 与最近的训练图拍摄间隔 ≤1 秒。

**诚实重评。** 我们改为**按整个场次划分**（任何一组连拍不跨训练/测试），并**从零重训**，同时设一个**随机划分对照组**：同样 35 只、同样 1743 张、每只张数完全一致——这样任何差距都只能归因于划分方式，而非数据变少。按场次划分的测试集近重复为 **0%**，对照组为 **10%**。

![泄露：随机划分 vs 按场次划分](figures/06_leakage_random_vs_session.png)

下表全部为 **macro**（每只企鹅等权重），由 `analysis/evaluate.py` 计算：

| macro 指标 | 随机划分（泄露） | 按场次划分（诚实） | 差距 |
|---|---|---|---|
| 检索 原型 top-1 | 0.920 | **0.389** | +0.531 |
| 检索 原型 top-5 | 0.984 | **0.726** | +0.258 |
| 检索 1-NN top-1 | 0.902 | **0.384** | +0.518 |

对照组**复现了 ~0.92 的头号数字**，所以掉分能干净地归因于划分方式。softmax 分类头也以完全相同的方式塌掉，这里不单列，因为识别接口是检索，而分类头的准确率只有按图片算的版本。区分能力其实来自一个"见过所有场次"的特征提取器——原来的 0.95/0.959 主要衡量的是*同场次*识别，高估了*跨场次*（换一天/换光线）的真实泛化。

> **两个必须写明的口径选择。**（1）*用 macro 不用 micro。* 测试集被少数拍得多的鸟主导（Medici 291 张，Beau 19 张），按图片算等于默默假设"游客最爱拍 Medici"，没有任何依据。（2）*原型 top-5 指最相似的 5 个类原型*，也就是 5 只**不同**的候选个体；而不是最相似的 5 张照片——那 5 张可能全属于同一只鸟，会高估"给饲养员一个候选名单"的实际帮助。

**开放集阈值**（`embedding_id/tune_openset.py`）——识别器还必须会说"我不认识这只"。用留一法模拟未知个体，已知 vs 未知的可分性实测 **AUC 0.991**；置信阈值从 **0.55 提到 0.80**，当时报告为"拒绝 96.6% 的未登记个体"。

> ⚠️ **这个数字后来被证明是错的。** 留一法模拟太容易了：那只"未知"的鸟本来就在训练集里，而且被主动推开过所有其他身份。用模型**真正从未训练过**的鸟来测（[§6](#6-交叉验证下的度量学习)），0.80 这个阈值**会接受 29.7% 的真陌生个体**。现在上线的值是 **0.938**。本段保留作为这个错误如何产生的历史记录。

**含义。** 真正的挑战是**跨场次泛化**（而非同场次准确率），且它受限于数据：44 只已登记个体中有 10 只只有一到两个拍摄场次。这引出了 [§6](#6-交叉验证下的度量学习) 里追查的两个抓手：**ArcFace 度量学习**与**为每只个体补拍多场次照片**。

**这次单一划分的已知局限。** 整个场次被整段分配给 train/val/test，所以每只鸟在测试集里有几张，取决于那个场次恰好包含多少张——从 **1 张（Beau、Spider、Not Tiki）到 43 张（Medici）**，实际测试占比从 2.7% 到 42%，而名义目标是 15%。样本最少的那几只鸟在这里算出的统计量几乎没有意义；[§6](#6-交叉验证下的度量学习) 用交叉验证消除了这个局限。

脚本：`analysis/leakage_audit.py`、`analysis/build_session_splits.py`、`analysis/session_disjoint_eval.py`、`analysis/evaluate.py`、`embedding_id/tune_openset.py`。

## 6. 交叉验证下的度量学习

§5 给出的估计诚实但脆弱：整个场次被分给某一个划分，导致好几只个体只凭一两张照片被评判。本节用交叉验证取代这一次性抽签，并用它来衡量度量学习。

**协议**——开跑前就已定死，所有参与比较的配置完全一致。

- **按场次的 5 折交叉验证**（`analysis/build_cv_folds.py`）。被分组的是*场次*，绝不是单张照片。每个场次分给「(这只鸟已在该折的照片数, 所有鸟已在该折的照片数)」最小的那一折；第二个键很关键——只按单只鸟平衡的话，每只鸟最大的场次都会堆进第 0 折，让它只剩 59% 的训练数据而不是 80%。结果：五折都是 **~80% 训练 / ~350 张测试**。
- **1743 张照片每一张都恰好被测一次**，而且测它的模型从没见过它的拍摄场次——对比之下，单次划分只有 261 张被测过。像 Beau 这样的鸟是用它全部 19 张照片评判，而不是 1 张。
- **固定 80 epoch、cosine 退火、无验证集、无早停**，取最后一个 epoch（`train_metric.py`）。这样训练数据保住 80%，同时消除了「按验证集挑 checkpoint」这个偏差来源。
- 配置之间用**配对 bootstrap** 比较 macro 差值——同一批重采样图片同时作用于两个配置——比"看两个独立置信区间是否重叠"敏感得多。

![每只个体的评估覆盖](figures/11_evaluation_coverage.png)

**结果**（`analysis/eval_cv.py`，macro，1743 张照片）。「损失 × 增强」四宫格**全部跑齐**，所以每个改动都能单独归因，不再混淆。置信区间是 95% **按场次聚类**的 bootstrap——同一串连拍里的照片几乎是重复的，按单张照片重采样会把相关样本当成独立样本，给出过窄的区间。

| 配置 | rank-1（35 选 1） | rank-5 | mAP | rank-1（81 选 1，全群） |
|---|---|---|---|---|
| softmax + basic | 0.390 [0.359, 0.434] | 0.746 [0.709, 0.787] | 0.420 [0.394, 0.463] | 0.224 [0.194, 0.262] |
| softmax + strong | 0.530 [0.490, 0.585] | **0.809** [0.775, 0.842] | 0.533 [0.501, 0.585] | 0.361 [0.322, 0.410] |
| ArcFace + basic | 0.486 [0.447, 0.543] | 0.734 [0.706, 0.784] | 0.509 [0.475, 0.563] | 0.364 [0.332, 0.404] |
| **ArcFace + strong** | **0.559** [0.517, 0.610] | 0.782 [0.751, 0.823] | **0.581** [0.543, 0.636] | **0.477** [0.436, 0.524] |

基线的交叉验证结果 **0.390 复现了 §5 单次划分的 0.389**，说明交叉验证没有引入偏差，这些提升是在一个被验证过的基线上量出来的。

### 到底是哪个改动起了作用

![损失 × 增强](figures/12_loss_x_augmentation.png)

对每个主效应做配对 bootstrap：

| 效应 | rank-1（35 选 1） | rank-1（81 选 1） | mAP |
|---|---|---|---|
| **只加强增强**（softmax+basic → softmax+strong） | **+0.141** [+0.105, +0.179] | +0.137 [+0.103, +0.174] | +0.113 [+0.087, +0.141] |
| **只换 ArcFace**（softmax+basic → ArcFace+basic） | +0.096 [+0.061, +0.139] | +0.140 [+0.110, +0.173] | +0.088 [+0.057, +0.124] |
| **已有强增强再加 ArcFace**（softmax+strong → ArcFace+strong） | +0.029 **[−0.005, +0.060]** | +0.116 [+0.082, +0.148] | +0.048 [+0.019, +0.072] |

由此得到三条结论，第三条最值得注意：

1. **数据增强是更大的那个杠杆**（+0.141 对 ArcFace 的 +0.096），而且在所有指标上都显著。合并效果 +0.169 是**次可加**的：两个单独效应之和为 +0.237，交互项为 −0.068——说明两者在部分地治同一个病。
2. **两者各自独立有效。** 加在原始基线上时，两个区间都不含 0。
3. **ArcFace 的*边际*价值取决于任务有多难。** 在已经有强增强的情况下，它在 35 选 1 的 rank-1 上只加 **+0.029 [−0.005, +0.060]**——*无法与噪声区分*。但同样这批模型，在全群 81 只中排序时加 **+0.116 [+0.082, +0.148]**，在 mAP 上加 **+0.048 [+0.019, +0.072]**。度量学习塑造的是**整个嵌入空间的几何结构**，而不是小候选集上的第一名判断，所以它的贡献恰好随底库变大而显现——那正是这类方法被设计出来要面对的场景，也正是真实种群所处的场景。

更早的单次划分曾暗示损失占了约三分之二的功劳。**那个读数是错的**：单次划分下有好几只个体只凭一两张照片被评判，交叉验证的四宫格把顺序颠倒了过来。

![CMC 曲线](figures/07_cmc_curve.png)

mAP 和 rank-1 同步上涨、没有掉队，说明提升来自**整个排序变好**，而不是第一名蒙对了。CMC 曲线也是"候选名单"这个交互设计的依据：给饲养员列 5 个候选，**78%** 的情况下正确答案在里面，而只给一个答案时是 **56%**。

**准确率由每只个体的拍摄场次数决定，而不是照片数量：**

| 拍摄场次数 | 个体数 | softmax + basic | ArcFace + strong |
|---|---|---|---|
| 3 个 | 8 | 0.081 | **0.186** |
| 4–6 个 | 13 | 0.423 | **0.618** |
| 7 个以上 | 14 | 0.535 | **0.717** |

![准确率 vs 拍摄场次数](figures/08_accuracy_vs_sessions.png)

度量学习把每一档都拉高了，但**救不了只有 3 个场次的鸟**：它们仍停在 0.186 这个不可用的水平，其中 Greyjoy 在两个配置下都从未被认出。排除这 8 只，其余 27 只达到 **0.669**。所以两个抓手是互补的——ArcFace 只能利用已经存在的场次多样性，而多样性本身只能靠补拍创造。

![每只个体的变化](figures/09_per_individual_change.png)

> **对一个旧结论的更正。**「35 只里有 12 只从未被认对」是单次划分下一两张测试图造成的假象。用每只鸟的全部照片评估，基线只有 2 只，ArcFace 只有 1 只。

### 开放集识别

rank-1 默认"镜头前这只鸟一定已经登记过"。实际使用中系统会不断被问到陌生个体，它必须**拒识**而不是从已有名单里挑一个最像的。

**这里用的是真冒充者。** 46 只从未进入任何一折的种群成员、共 564 张照片被用作陌生集——模型**从来没有训练过**它们。早先的版本是把查询自己的原型藏起来、取次优当作"未知"，那个模拟**太容易了**：那只鸟本来就在训练集里，而且被主动推开过所有其他身份。模拟的结果高估得很厉害，下表把两个数字并列，让偏差大小一目了然。

| 工作点 | softmax + basic | **ArcFace + strong** | 模拟冒充者曾声称 |
|---|---|---|---|
| DIR @ FAR = 1% | 0.076 | **0.123** | 0.230 |
| DIR @ FAR = 5% | 0.134 | **0.237** | 0.361 |
| DIR @ FAR = 10% | 0.163 | **0.312** | 0.432 |

![开放集 DIR-FAR 曲线](figures/10_open_set_dir_far.png)

DIR@FAR=x 的含义是：在"陌生个体只有 x 的比例会被错误接受"这个阈值下，已登记的鸟中**既叫对名字、置信度又够高**的比例。**闭集 rank-1 的 0.559，在要求 99% 拒绝真陌生个体时掉到 0.123。** 描述部署可用性的是这个落差，不是闭集那个数字——它说明系统在"还必须会拒绝"的前提下尚不可靠。ArcFace 在每个工作点上都把 DIR 翻了近一倍，说明度量学习改善的不只是排序，还有置信度的分离。

### 部署模型

交叉验证产出的是**性能估计**，不是一个能上线的模型。因此部署用的提取器以**完全相同的配方**在**全部个体、全部照片**上重训（79 只、2304 张、无留出集，`train_metric.py --deploy`），底库则登记**全部 81 只、2307 张**（`embedding_id/build_gallery.py`）。

两个刻意的不对称，都源于"检索"而非"分类"的设计：

- **入库不需要场次多样性，诚实的*评估*才需要。** 不在底库里的鸟永远无法被识别，只能被拒绝，所以照片太少、无法评估的个体照样入库。其中两只连训练都参与不了，纯粹作为向量存在——这正是当初选择检索路线的理由：**加一只新企鹅是入库，不是重训**。
- **不留出任何数据。** 现在再扣下数据只会让上线的模型变弱，而估计值早已有了。

置信阈值是 **0.938**，在交叉验证模型上针对真陌生个体、于 FAR = 5% 处实测得到。此前的 0.80 是在泄漏划分上针对模拟未知调出来的，文档里写着"拒绝 96.6% 的未登记个体"，**实测却接受 29.7%**。引用这个阈值时必须同时说明两条限制：它是从交叉验证模型**迁移**来的，因为部署模型训练了全部个体，群内已不存在真正的陌生个体可供标定；以及全部 81 只入库后，现实中的"未知"不再是未登记的鸟，而是**一张坏照片**——拍糊、拍到背面、或者根本不是企鹅——而这个阈值从未针对那种情况标定过。

## 7. 旗舰方案：Embedding 检索 + RAG

核心方向：把分类器升级为**多模态检索 + 检索增强生成（RAG）**应用。

### 流水线
```
游客照片
   │
   ▼
[检测 + 正面过滤]  ── 非正面 / 非企鹅 ──▶ “请重拍”
   │
   ▼
[图像 embedding 模型]  （ArcFace 训练的 backbone，或 CLIP / DINOv2）
   │  照片 → 向量
   ▼
[向量数据库：企鹅底库]  （FAISS / Qdrant / Milvus / pgvector）
   │  ANN 检索 top-k 已注册向量
   ▼
[匹配 + 开放集阈值]  ── 距离过大 ──▶ “未知个体”
   │  身份 = Cooper
   ▼
[知识检索 — RAG]
   ├─ Cooper 的结构化档案（名字、年龄、性别、脚环颜色、性格、习性、饲养员备注）
   └─ 企鹅通用知识片段（物种生物学、种群、保育）
   │
   ▼
[LLM 基于检索文档生成]  → 名字、特征、习性、回答游客问题
```

### RAG 的两种角色（同时使用）
1. **档案 grounded 生成**——识别出身份后，取该个体的档案文档，让 LLM 生成自然语言介绍。grounding 能防止模型**对一只真实、有名字的动物编造事实**——这是这里用 RAG 的一个具体、站得住脚的理由。
2. **开放域问答**——一个知识库（企鹅生物学、种群、饲养、保育）切块 + 向量化；游客自由提问时检索相关片段 → 有引用来源的 grounded 回答。

### 可选的 Agent 层
一个 LLM agent 编排工具：`identify_penguin(image)`、`get_profile(name)`、`search_knowledge(query)`——由模型决定调用哪个。这在一个系统里同时展示 **AI agent + 多模态检索 + RAG**。

### 产品形态：可对话的洪堡企鹅专家
面向用户的外壳是一个聊天窗口。用户扫码 / 打开 App 进入时，机器人主动打招呼：

> 🐧 你好！我是这里的**洪堡企鹅专家**。拍一张企鹅的**正面全身照**发给我，我就能告诉你它是哪一只，以及它的名字、生日、性格和小故事～ 关于企鹅的任何问题也都可以问我！

- **人设** = agent 的 system prompt（亲切、简洁，像热情的饲养员）。
- **照片 → 身份**：收到企鹅照片触发 `identify_penguin`，再用 `get_profile` 介绍这一只。
- **问题 → 知识**：通用企鹅问题触发 `search_knowledge`。
- **会话记忆**：把本次识别出的企鹅存进会话状态，后续追问（"它几岁？"）无需重新上传照片。
- **不确定时优雅处理**：置信度低 / 非正面照时，请用户重拍清晰正面照，而不是硬猜。
- **事实 grounding**：关于某只企鹅的事实只来自 `get_profile`，字段缺失就如实说没有，绝不编造——这是防幻觉的核心保证。

### 建议技术栈
- **图像 embedding**：当前用 exp1 的 ResNet18 作冻结特征提取器（exp3）；计划训练 ArcFace backbone，并与开箱即用的 **DINOv2 / CLIP** 做对照。
- **向量数据库**：FAISS（简单/本地）→ **Qdrant**（更有生产感）做 demo。
- **文本 embedding**：开源 `bge` / `e5`，用于知识库。
- **LLM**：**本地部署的开源模型**（如 Qwen / Llama），可选在企鹅资料上做 **LoRA 微调**——自建部署而非付费 API——做 grounded 生成 + 引用。
- **服务**：FastAPI 后端 + Streamlit/Gradio demo 前端。
- **评测**：检索命中率（top-k）、回答 **忠实度/grounded 程度**、开放集拒识精度。

### 技术范围
本方案综合了细粒度计算机视觉、**度量学习**、**向量数据库**、**多模态 RAG**、**带防幻觉护栏的 grounded LLM 生成**与 **RAG 评测**，并应用于真实数据集。

### 当前状态与下一步
**已完成**——CNN 检索路线（exp3）：一个可用的 **FAISS 向量数据库**，支持**增量注册**（新企鹅存入特征即可登记，无需重训）与**开放集拒识**（阈值经留一法调到 **0.80**，AUC 0.991；照片模糊/未登记 → 拒识而非张冠李戴）。一次**数据泄露审计**（[§5](#5-数据泄露审计与跨场次评估)）确立了诚实的基线，随后 **ArcFace 度量学习 + 5 折交叉验证**（[§6](#6-交叉验证下的度量学习)）把跨场次识别从 **macro 0.390 提升到 0.559**。分类器路线仅保留作基线；**检索是今后的识别方式**。

**下一步**
1. **给覆盖不足的鸟补拍（优先）。** 两个缺口都只能靠相机解决：**37 只完全不在系统里的个体**，以及**8 只只有 3 个拍摄场次的已登记个体**——度量学习把后者留在 0.186。需要的是**换一天、换光线**去拍，同一串连拍里多按几张快门没有用。
2. **补齐评估体系**——在 macro rank-1 之外加上 mAP 与 CMC，以及开放集 **TAR@FAR**，用于回答闭集准确率无法衡量的那个问题："这只鸟到底登记过没有？"
3. **训练并交付部署模型**——用全部 1743 张照片训一个 ArcFace 模型，性能声明引用 §6 的交叉验证估计。
4. **建立整洁的企鹅档案库**——每只一份结构化记录（姓名、出生日期、性格、特征、习性、脚环颜色），用于给 `get_profile` 做事实支撑。
5. **搭建 agent 主循环**——用 LLM 的 function-calling / tool-use 编排 `identify_penguin` / `get_profile` / `search_knowledge`，并带会话记忆。
6. **对话式洪堡企鹅专家界面**——聊天窗口，含上文的欢迎语与会话记忆。

## 9. 复现方式

```powershell
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
pip install numpy pillow ultralytics matplotlib python-docx
```

训练分类器：
```powershell
# 实验一：全身照
python train_experiment1.py --data-dir penguins_dataset_split --epochs 30 --batch-size 32
# 实验二：肚子裁剪
python train_experiment1.py --data-dir penguins_dataset_split_belly_by_yoloV8 --epochs 50 --batch-size 32
```

数据泄露审计与诚实的跨场次评估（§5）：
```powershell
# 量化当前划分里的连拍/场次泄露
python analysis/leakage_audit.py
# 构建按场次划分 + 随机对照划分，然后重训并对比
python analysis/build_session_splits.py
python train_experiment1.py --data-dir penguins_dataset_split_session_disjoint --output-dir runs/exp1b_session_disjoint
python train_experiment1.py --data-dir penguins_dataset_split_session_random  --output-dir runs/exp1b_random_control
# 对两个重训模型做 macro 评估
python analysis/evaluate.py
# 调开放集拒识阈值（留一法）
python embedding_id/tune_openset.py
```

交叉验证下的度量学习（§6）——RTX 4060 上每折约 11 分钟，全部约 1 小时 50 分：
```powershell
# 把拍摄场次分成 5 个均衡的折（写出 analysis/artifacts/cv_folds.json）
python analysis/build_cv_folds.py
# 基线与 ArcFace，各 5 折，固定 80 epoch，无早停
python train_metric.py --loss softmax --aug basic  --all-folds
python train_metric.py --loss arcface --aug strong --all-folds
# 四宫格剩下的两格
python train_metric.py --loss softmax --aug strong --all-folds
python train_metric.py --loss arcface --aug basic  --all-folds
# 汇总各折：macro rank-1/rank-5/mAP/CMC/开放集，四格一起
python analysis/eval_cv.py cv_softmax_basic cv_softmax_strong cv_arcface_basic cv_arcface_strong
# 单独检验每个主效应（配对检验每次只能两个配置）
python analysis/eval_cv.py cv_softmax_strong cv_arcface_strong --out analysis/artifacts/cv_pair_loss_given_strong.json
# 由 JSON 结果重绘图 06-12
python analysis/plot_figures.py
```
